# Product feedback

## Tools and purpose

Codex was used to develop and test the application. The official TypeScript MCP SDK implements the self-hosted server and client interoperability tests. React and Vinext render the interface; Cloudflare Workers and D1 support the operator workspace. Drizzle describes the database and migrations. The OpenAI Sites Vite plugin supplies local development sign-in.

## What worked

The MCP SDK allowed the same inspect, probe and receipt tools to serve the browser workflow and SDK-client tests. Structured tool outputs retain the exact decision, checked rules and changed facts. D1 transaction batches and revision checks keep committed inventory changes and receipts together.

## What needs work

Alexa+ preview tooling was unavailable to participants, so this entry demonstrates the permitted self-hosted MCP route with its own frontend. The project does not claim Alexa+ distribution. The build emits Vinext JSON-import and route-classification warnings despite passing. Cross-origin HTTP checks also exposed that Vinext can reject a request before the route executes; tests distinguish the framework response from route-level guards.

## Onboarding

A small deterministic desk model came first. The MCP layer then exposed read-only inspection and independent request comparisons. The main additional work was integrating authenticated private storage, reproducible local migrations and a fictional demo that judges can run without credentials.

## Would I use these tools again?

Yes to the MCP SDK for typed tools and explicit outputs, and D1 for this small transactional desk. I would evaluate Alexa+ distribution once its developer tools are accessible. That recommendation is based on the self-hosted MCP implementation; no Echo device or Alexa+ production deployment was tested.
